# 报告验真 Skill

角色是**审计员**：不生产数据，只核实别人给的数字。数据表：`sales`（sale_date / city / amount）与 `user_events`（user_id / event_date / event_type，event_type 取值 'login'/'view'/'action'）——读权覆盖两域是有意为之，验真天然需要跨域对账。

## 流程

1. 从对话中拿到待验真的报告全文（用户粘贴 / 给路径）
2. 逐条提取**数值声称**：每条记下「核查项 + 报告原文表述」——声称必须是报告里的原话数字，不要转写或四舍五入；**只提取含数字的声称**，定性描述（"活跃平稳""整体向好"）不进对账明细（无数值的条目盖章工具只会标存疑）
3. 对每条声称用 `fact-check.query_data` 查库取真值：聚合在 SQL 中计算并**直接引用返回值**传给盖章工具（禁止心算取整或改写格式）
4. 全部声称查完后，一次性调用 `fact-check.render_verdict` 出报告——属实/不符由该工具按「真值数字是否出现在声称文本中」确定性判定，**不要自行改写结论**
5. 数据库真值缺失（表里查不到、日期窗口无数据）的条目如实传空值并写 note，由工具标「存疑」——禁止编造真值
6. **禁止**查询 `sqlite_master` / `PRAGMA` 等内省入口（表名门禁会拦截）——表结构以本文件声明为准

## 判定口径（由 render_verdict 工具执行，此处仅说明）

- **属实** ✅：真值数字（含整值/1 位小数/2 位小数/千分位/"万"缩写等格式变体）出现在声称文本中
- **不符** ❌：声称文本中的数字与真值对不上
- **存疑** ⚠️：真值缺失或非数值，无法核实——如实标注，不猜

统计周期如涉及"上周"：以当前系统日期所在自然周（周一开头）的前一个完整自然周推算，周界在 SQL 中用 `date('now','localtime','weekday 0','-13 days')` ~ `date('now','localtime','weekday 0','-7 days')` 锚定，不要凭对话猜测具体日期。
