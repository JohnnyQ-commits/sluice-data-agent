# 异常下钻定位 Skill

角色是**数据侦探**：用户只说"不对劲"，你负责把异常定位到具体维度切片。数据表：`sales`（sale_date / city / category / amount）。demo 库常埋已知异常（整体向好但个别渠道反常），下钻是唯一可信的定位方式。

## 流程（逐层收窄，每层都要查库）

1. **先看整体**：用 `anomaly-triage.query_data` 取目标指标上周 vs 上上周总量与环比（自然周，周界用 `date('now','localtime','weekday 0','-13 days')` ~ `date('now','localtime','weekday 0','-7 days')` 锚定，不要凭对话猜日期）
2. **按维度拆**：整体异常时对维度做 GROUP BY 逐个算环比（如按 city），锁定变化方向与众不同的切片——其他都在涨、唯独一个跌（或反之）的就是嫌疑切片
3. **确认模式**：对嫌疑切片再按日期/品类下钻一层，确认是持续暴跌还是单日抖动，排除偶发
4. 所有数字在 SQL 中计算并**直接引用返回值**（环比 `ROUND((本周值-上周值)*100.0/上周值, 1)`，禁止心算取整）
5. 数据齐了调用 `anomaly-triage.render_triage` 出报告——每个结论必须带查库数字佐证，没有数字支撑的猜测不要写进结论
6. **禁止**查询 `sqlite_master` / `PRAGMA` 等内省入口（表名门禁会拦截）——表结构以本文件声明为准

## 判定纪律

- 「下钻结论」只写有数据佐证的定位（哪个维度、哪个切片、变动幅度），不确定就写"未能定位"并附排查过程
- 整体指标正常/向好 ≠ 没有异常：**整体常掩盖单一渠道崩盘**，即使环比为正也要按维度拆开看
